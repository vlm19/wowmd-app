원본을 변경하지 않고 Markdown 열기

파일 선택기나 드래그 앤 드롭으로 로컬 .md 및 .markdown 파일을 열거나, 확장 프로그램에서 지원되는 공개 GitHub Markdown을 이어서 작업할 수 있습니다.

리뷰는 브라우저에서 진행되며 원본에 다시 쓰지 않습니다. 검토 사본 저장은 주석을 이어받은 별도의 Obsidian용 .md 후속 버전을 만듭니다.

버전 기록에서 현재 문서 계보로 만든 브라우저 로컬 후속 버전을 다시 열 수 있습니다.

유형화된 리뷰: 단순한 색상이 아닌 네 가지 판단

wowMD에서 텍스트를 표시하면 후속 행동을 포함한 판단이 기록됩니다. 이 유형들은 Notes 패널, 전체 리뷰 맵, Ticket JSON 범례에 반영됩니다.

확인 필요이 지점을 본질을 바꾸지 않고 설명하거나 명확히 하세요.
의문 있음이 주장을 검토하세요. 부정확할 수 있으며 수정이 필요할 수 있습니다.
중요이 핵심 지점을 유지하고 강조하세요.
확인 완료검토 완료 및 정확함. 조치 필요 없음.

버전 간 유지

원본 문서가 변경되면 wowMD는 선택된 인용문과 주변 컨텍스트를 사용하여 주석을 동일한 문단에 재고정하려고 시도합니다. 문단이 완전히 사라지면 마크는 분리 상태가 되며 찾기 기능으로 수동 복구할 수 있습니다.

재고정은 비파괴적입니다. wowMD는 주석 위치를 재계산하며, 원본 파일에 다시 쓰지 않습니다.

티켓 JSON: 여러분의 판단을 AI 작업 지시로

티켓은 문서 스냅샷, 이중 언어 유형 범례, 섹션 컨텍스트, 선택된 인용문, 메모, 대체 제안을 하나로 묶습니다. 원시 주석을 백업 및 재가져오기용으로 저장하는 백업 JSON과는 다릅니다.

  1. 클릭
  2. 원하는 AI 도구를 여세요.
  3. 아래 프롬프트를 붙여넣은 후 티켓 내용을 붙여넣으세요.
당신은 꼼꼼한 편집자입니다. Markdown 문서에 대한 제 주석이 담긴 JSON 티켓을 전달합니다.
각 항목을 유형별로 처리하고 수정된 전체 문서를 출력하세요.
- clarify: 본질을 바꾸지 않고 설명하거나 명확히 하기
- dispute: 검토하고, 틀렸다면 수정 후 이유 설명
- important: 유지하고 강조
- confirmed: 그대로 유지
기본 문서로 document.markdownSnapshot을 사용하세요. headingPath, quote, prefix, suffix로 각 항목을 찾으세요. suggestedReplacement가 있으면 우선 사용하세요.
티켓:
&lt;내보낸 티켓 JSON을 여기에 붙여넣으세요&gt;

저장, 백업 및 복구

저장된 주석과 가져온 GitHub 문서 사본은 일반 브라우저 캐시가 아닌 사이트 데이터를 사용합니다. 로컬 파일은 세션 입력으로 유지되며 주석은 문서 지문별로 저장됩니다.

사이트 데이터 삭제, 비공개 브라우징, 다른 브라우저·프로필·기기 사용, 저장소 회수로 브라우저 로컬 작업이 사라질 수 있습니다. 저장하지 않은 툴바 초안도 새로고침이나 충돌 후 손실될 수 있습니다.

다시 가져올 수 있는 주석 데이터는 Backup JSON으로, 사람이 읽을 리뷰 문맥은 Reviewed Markdown으로, 완성된 결과물은 장기 보관용으로 내보내세요.

내보내기

HTML 내보내기는 사람을 위한 것입니다: 구조, 하이라이트, 노트를 담은 오프라인 읽기용 단일 파일입니다.

검토 Markdown은 Obsidian용입니다: 리뷰 callout, 태그, properties를 담은 새 .md 사본입니다. 원본을 수정하지 않고 제안된 대체 문구도 적용하지 않습니다.

백업 JSON은 백업과 재가져오기를 위한 원시 주석 데이터입니다.

티켓 JSON은 AI나 편집자를 위한 것입니다: 유형화된 판단으로 만든 작업 지시입니다.
