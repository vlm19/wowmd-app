从让 wowMD 与众不同的核心概念开始：类型化审阅、跨版本存活、给 Obsidian 的审阅版 Markdown，以及可以交给 AI 的工单。

打开 Markdown，不改动原文

通过文件选择器或拖放打开本地 .md 与 .markdown 文件，也可以从扩展继续处理受支持的公开 GitHub Markdown。

审阅在浏览器中完成，绝不写回原文。保存审阅副本会创建单独的 Obsidian-ready .md 后继版本，并延续标注。

版本历史可重新打开由当前文档谱系创建的浏览器本地后继版本。

类型化审阅：四种判断，不只是颜色

在 wowMD 中标记文本时，你记录的是带有后续行动含义的判断。这些类型会驱动笔记面板、总体审阅地图和工单 JSON 图例。

跨版本存活

当源文档变化时，wowMD 会尝试用选中的引用文字和上下文将你的标注重新锚定到同一段落。如果某段文字确实消失，标注会变成孤儿状态，可通过 Find 手动恢复。

重新锚定是非破坏性的。wowMD 重新计算标注位置；它不会写回源文件。

工单 JSON：你的判断变成 AI 工作指令

工单打包了文档快照、双语类型对照表、章节上下文、选中引文、备注和建议替换。它与备份 JSON 不同——备份 JSON 只存储原始标注数据用于备份和重新导入。

存储、备份与恢复

已保存标注和导入的 GitHub 文档副本使用浏览器站点数据，而不是普通浏览器缓存。本地文件仍是会话输入；wowMD 按文档指纹保存其标注。

清除站点数据、使用隐私模式、更换浏览器、配置文件或设备，以及存储被回收，都可能移除浏览器本地工作。未保存的工具栏草稿也可能在刷新或崩溃后丢失。

导出备份 JSON 以保留可重新导入的标注数据，导出审阅版 Markdown 以保留可读审阅上下文，并保存完成的交付产物用于长期保管。

典型工作流

选择任务，沿着审阅路径完成工作。

每个工作流都连接真实输入、合适的审阅动作、关注重点和最佳交付产物。

开发者阅读开源项目 README快速找到安装命令、API、限制和警告。
  1. 01使用 Chrome 扩展打开
  2. 02通过目录导航并折叠章节
  3. 03检查命令、代码和表格
  4. 04仅在需要深度审阅时进入 Pro
最佳结果快速结构化阅读，无需导出
产品经理审阅 AI 生成的产品规格把模糊或可疑内容转化为可执行的修订说明。
  1. 01打开规格并扫描整体结构
  2. 02标记澄清、争议、重点和已确认内容
  3. 03用 Overall Review Map 找到薄弱章节
  4. 04向 AI 交付精确修订指令
最佳结果Ticket JSON
工程师审阅技术实现方案把架构风险和修正意见绑定到准确原文。
  1. 01搜索 API、模块和迁移步骤
  2. 02标记风险争议与关键不变量
  3. 03添加备注与建议替换
  4. 04交付行动项和可读审阅记录
最佳结果Ticket JSON + HTML
知识工作者构建 Obsidian 知识库保留个人判断，同时不改动原始文档。
  1. 01打开本地 Markdown
  2. 02标记核心观点、问题和可信段落
  3. 03保存单独的审阅后继版本
  4. 04将审阅副本放入知识库
最佳结果面向 Obsidian 的 Reviewed Markdown
开发者迭代 Agent Skill 或工作流指令保护已验证规则，同时修正歧义、冲突和缺失的失败处理。
  1. 01检查触发条件、工具顺序、约束和回退方案
  2. 02记录类型化判断并提出准确替换
  3. 03找到审阅缺口和冲突集中章节
  4. 04让 AI 修订，再审阅下一个版本
最佳结果Ticket JSON + 下一轮审阅

导出

HTML 导出面向人：一个可离线阅读的文件，保留结构、高亮和备注。

审阅版 Markdown 面向 Obsidian：新的 .md 副本，包含审阅 callout、标签和属性。它不会修改原文件，也不会应用建议替换。

备份 JSON 用于备份和重新导入：原始标注数据。

工单 JSON 面向 AI 或编辑：由你的类型化判断生成的工作指令。
