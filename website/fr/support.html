Support

Guide et retours pour la boucle de relecture.

Commencez par les concepts qui distinguent wowMD : la relecture typée, la survie inter-versions, le Markdown révisé pour Obsidian et le ticket que vous pouvez transmettre à une IA.

Ouvrir du Markdown sans modifier l’original

Ouvrez des fichiers locaux .md ou .markdown avec le sélecteur ou par glisser-déposer, ou continuez depuis un Markdown GitHub public pris en charge via l’extension.

La relecture se fait dans le navigateur et ne réécrit jamais l’original. Enregistrer la copie relue crée un successeur .md séparé, compatible Obsidian, et transmet les annotations.

L’historique des versions permet de rouvrir les successeurs locaux au navigateur créés dans la lignée du document actuel.

Relecture typée : quatre jugements, pas seulement des couleurs

Lorsque vous marquez du texte dans wowMD, vous consignez un jugement associé à une action. Ces types alimentent le panneau de notes, la Carte globale de revue et la légende Ticket JSON.

À clarifierExpliquez ou clarifiez ce point sans en changer le fond.
ContestéExaminez cette affirmation ; elle pourrait être incorrecte et nécessiter une correction.
ImportantConservez et soulignez ce point clé.
ConfirméVérifié et correct ; aucune action nécessaire.

Survie inter-versions

Quand le document source change, wowMD tente de réancrer vos annotations au même passage en utilisant la citation sélectionnée et le contexte environnant. Si un passage disparaît vraiment, la marque devient orpheline et peut être récupérée manuellement avec Rechercher.

Le réancrage est non destructif. wowMD recalcule les positions des annotations ; il ne modifie pas le fichier source.

Ticket JSON : vos jugements comme ordre de travail pour l'IA

Un ticket regroupe l'instantané du document, une légende bilingue des types, le contexte de section, les citations sélectionnées, les notes et les remplacements suggérés. Il diffère du Backup JSON, qui stocke les annotations brutes pour sauvegarde et réimportation.

Stockage, sauvegarde et récupération

Les annotations enregistrées et les copies de documents GitHub importés utilisent les données de site du navigateur, pas son cache ordinaire. Les fichiers locaux restent des entrées de session ; leurs annotations sont stockées par empreinte de document.

Effacer les données du site, utiliser la navigation privée, changer de navigateur, de profil ou d’appareil, ou subir une éviction du stockage peut supprimer le travail local. Les brouillons non enregistrés peuvent aussi être perdus après actualisation ou plantage.

Exportez Backup JSON pour les annotations réimportables, Reviewed Markdown pour un contexte de relecture lisible, et les livrables terminés pour la conservation à long terme.

Export

L'export HTML est destiné aux humains : un fichier lisible hors ligne avec structure, surlignages et notes.

Le Markdown révisé est destiné à Obsidian : une nouvelle copie .md avec callouts de relecture, tags et propriétés. Il ne modifie pas l'original et n'applique pas les remplacements suggérés.

Backup JSON sert à sauvegarder et réimporter : les données d'annotation brutes.

Ticket JSON est destiné à une IA ou un éditeur : un ordre de travail construit à partir de vos jugements typés.
